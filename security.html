Helmet — HTTP security headers

Every response carries headers that tell the browser how to behave safely, before any attack script even runs.

Content-Security-PolicyOnly allows scripts, styles, and images from the site's own origin — blocks injected scripts.
X-Frame-OptionsStops other sites from embedding this page in an invisible iframe (clickjacking).
X-Content-Type-Options: nosniffStops the browser from misinterpreting a file's type in an exploitable way.
Strict-Transport-SecurityTells browsers to always use HTTPS once the site is deployed with it.

express-rate-limit — brute-force protection

Login, signup, and admin-login are capped at 20 attempts per 15 minutes per IP address. Past that, the server rejects the request before ever checking the password.

HTTP/1.1 429 Too Many Requests
{ "error": "Too many attempts. Please wait a while and try again." }

csurf — Cross-Site Request Forgery protection

The attack: a malicious page open in another tab quietly submits a request using your logged-in session — without you clicking anything.

Without protection

  • Admin is logged into the dashboard
  • Admin opens a malicious link in another tab
  • That page silently submits a request to delete a product
  • The browser auto-attaches the admin's session cookie
  • Product gets deleted — admin never clicked anything on the real site

With csurf

  • The page first fetches a one-time token from GET /api/csrf-token
  • Every POST / PUT / DELETE must include that token in a header
  • The malicious page has no way to read or guess that token
  • Its forged request arrives without a valid token
  • Server responds 403 — request rejected before it does anything

Password security — Node's built-in crypto

Passwords are never stored as plain text — no separate library needed, just Node's own crypto module.

1

Salt

A random string per user, so identical passwords produce completely different stored values.

2

scrypt hash

A deliberately slow, memory-heavy algorithm that makes brute-forcing expensive.

3

timingSafeEqual

Compares hashes in constant time, so timing differences can't leak the answer.

Signup also requires a strong password: at least 8 characters, with an uppercase letter, a lowercase letter, a number, and a special character.

Session cookies — httpOnly & SameSite

HttpOnly

Client-side JavaScript cannot read this cookie at all — so even a malicious script on the page couldn't steal the login token.

SameSite = Lax

The cookie isn't sent along with requests from other websites — an extra layer against forged cross-site requests.

Server-side authorization rules

Admin-only actionsAdd, edit, delete products, and view all customers/orders require an active admin session.
Customer-only actionsPlacing an order and viewing order history require an active customer session tied to that account.
Purchase-gated reviewsA customer can only review a product after their order history shows they actually bought it — checked against real order records, not a hidden UI flag.

Limitations & future work

No HTTPS yet

Fine for local testing; a real deployment needs TLS, usually via the hosting platform.

Sessions live in memory

Restarting the server logs everyone out — a real deployment should persist sessions.

csurf is unmaintained upstream

Still works correctly today; csrf-csrf is the actively maintained successor.

No session expiry yet

Sessions last until logout or restart — an idle timeout would tighten this further.

Security isn't a feature — it's a habit built into every route.
